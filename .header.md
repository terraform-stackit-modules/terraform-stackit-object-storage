# Terraform STACKIT Object Storage module

Terraform module which manages a [STACKIT Object Storage](https://registry.terraform.io/providers/stackitcloud/stackit/latest/docs/resources/objectstorage_bucket) bucket and its S3 credentials on [STACKIT](https://www.stackit.de/en/), with optional Object Lock, a project compliance lock and a bucket default-retention policy.

This repository is not from the official STACKIT organization.

## Usage

```hcl
module "object_storage" {
  source  = "terraform-stackit-modules/object-storage/stackit"
  version = ">= 1.0.0"

  project_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
  name       = "my-bucket"

  credentials_groups = {
    app = {
      name = "app-credentials"
      credentials = [
        { name = "primary", expiration_timestamp = "2027-01-02T03:04:05Z" },
      ]
    }
  }
}
```

The generated S3 secret access keys are exposed via the `credential_secret_access_keys`
output, which is marked **sensitive**.

## Object Lock, compliance lock and default retention

STACKIT Object Lock (WORM) relies on a **project-level compliance lock**. To create a bucket
with immutable objects and a default retention policy:

```hcl
module "object_storage" {
  source  = "terraform-stackit-modules/object-storage/stackit"
  version = ">= 1.0.0"

  project_id = "xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
  name       = "compliant-bucket"

  create_compliance_lock = true   # project-scoped; see the warning below
  object_lock            = true    # requires an active compliance lock

  default_retention = {
    days = 30
    mode = "GOVERNANCE"            # or "COMPLIANCE"
  }
}
```

> ⚠️ **The compliance lock is project-scoped and irreversible.** Only one compliance lock may
> exist per STACKIT project, and it **cannot be destroyed** once created — `terraform destroy`
> will not remove it. Enable `create_compliance_lock` deliberately, and NEVER in a throwaway
> test run: it permanently affects the whole project. The default `examples/basic` intentionally
> leaves it disabled.

## Notes

- A bucket cannot be destroyed while it still contains objects — empty it first.
- `object_lock` can only be set at bucket creation and needs an active compliance lock.
- Only the **public** parts of credentials are non-sensitive; secret access keys are sensitive.

## Terratest

The `test/` directory holds a Terratest integration test that applies the `examples/basic` root module against a real STACKIT project (requires `STACKIT_SERVICE_ACCOUNT_KEY` and `STACKIT_PROJECT_ID`). The basic example deliberately does NOT create a compliance lock, so the test stays fully reversible.

```bash
cd test
go mod init github.com/terraform-stackit-modules/terraform-stackit-object-storage
go get github.com/gruntwork-io/terratest@v1.0.1
go mod tidy
go test -v -timeout 45m ./...
```
